# AI Management — инструкция публикации в ChatGPT Sites

## Что это

Рабочий кабинет задач компании с филиалами: сотрудник, руководитель филиала, директор.
Полный стек в одном репозитории: React + Tailwind CSS 4 + shadcn/ui (фронтенд),
серверные операции в стиле Next.js App Router на **vinext** (Vite), база **D1** (SQLite) через
Drizzle ORM, файлы в **R2**. Собирается в Cloudflare Worker `dist/server/index.js` (ES-модуль, экспорт `fetch`).

Вход — **собственные логин и пароль** (не «Вход через ChatGPT»). Аккаунт ChatGPT или Google посетителю не нужен.

## Требования

- Node.js **22.13 или новее**
- Сборка: `npm ci && npm run build`
- Результат: `dist/server/index.js` (Worker), `dist/client/` (статика), `dist/.openai/hosting.json` и `dist/.openai/drizzle/` (миграции)

## Привязки (`.openai/hosting.json`)

```json
{ "d1": "DB", "r2": "BUCKET" }
```

| Привязка | Тип | Назначение |
|---|---|---|
| `DB` | D1 (SQLite) | Все данные: компания, филиалы, пользователи, сессии, задачи, история, очередь уведомлений |
| `BUCKET` | R2 | Содержимое файлов (вложения, фото, голос). Метаданные — в D1 |

Формат файла взят из стартового шаблона Sites (vinext-starter): поля `d1` и `r2` содержат имена привязок.
`project_id` в репозитории **нет** — Sites дописывает его сам после создания проекта.
> Сверить: если в вашей версии Sites формат `hosting.json` отличается, приведите его к шаблону, имена привязок оставьте `DB` и `BUCKET`.

## Миграции

- Файлы: `drizzle/0000_init.sql`, `drizzle/0001_task_search.sql`, … (порядок — `drizzle/meta/_journal.json`).
- Сборка копирует их в `dist/.openai/drizzle/`; Sites применяет их к D1 **по порядку, до** того как новая версия получит трафик.
- Новая компания стартует с **чистой БД**: миграции создают только схему, без примеров и тестовых аккаунтов.
- Схема меняется **только новыми миграциями** (`npm run db:generate -- --name <описание>`). Применённые файлы не редактировать: откат версии возвращает код, но не данные.

## Секреты (Settings → Secrets сайта)

Значения в репозиторий не кладутся (см. `.env.example` — только имена).

| Секрет | Обязателен | Для чего |
|---|---|---|
| `OWNER_ACTIVATION_CODE` | **да**, для первого запуска | Код владельца для выпуска приглашения первого директора. Длинная случайная строка |
| `OPENAI_API_KEY` | нет | Помощник, распознавание голоса (этап 6) |
| `WHAPI_TOKEN` | нет | WhatsApp через Whapi (этап 7) |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | нет | Push-уведомления (этап 5). Сгенерировать: `npx web-push generate-vapid-keys` |

Без необязательных секретов кабинет работает; их состояние видно в «Профиль → Настройки системы → Подключения».

## Доступ к сайту

В настройках доступа Sites сайт должен быть **открыт для всех (Public)**. Иначе Sites покажет свой вход
и форма входа кабинета не откроется. Права проверяет сам кабинет на каждом запросе.

## Первый запуск: как создать первого директора

1. Задайте секрет `OWNER_ACTIVATION_CODE` и опубликуйте сайт.
2. Откройте `https://<адрес-сайта>/setup` (или ссылку «Первый запуск» на странице входа).
3. Введите код, название компании, часовой пояс (по умолчанию `Asia/Almaty`).
4. Получите **одноразовую** ссылку-приглашение директора (действует 72 часа). Повторный выпуск отзывает прежнюю.
5. Откройте ссылку, задайте имя, логин и пароль. Приглашение гасится только успешной регистрацией.
6. Директор создаёт филиал («Создать филиал») и выдаёт приглашения в «Профиль → Настройки системы → Приглашения».

После активации директора страница `/setup` закрывается (повторно директора этим путём не создать).

## Проверка после публикации

- `GET /api/health` → `{"ok":true,"build":"0.2.0","schema":"0001_task_search","bindings":{"db":true,"bucket":true}}`
- Чистый браузер открывает адрес сайта → форма входа кабинета.

## Локальная разработка

```bash
npm ci
cp .env.example .dev.vars            # заполнить OWNER_ACTIVATION_CODE
npm run db:migrate:local             # миграции в локальную D1 (Miniflare)
npm run dev                          # http://localhost:5173
```

| Команда | Что делает |
|---|---|
| `npm run build` | Сборка + проверка артефакта (`scripts/check-artifact.mjs`) |
| `npm run db:check` | Применяет все миграции к пустой SQLite в памяти, проверяет чистый старт |
| `npm test` | Юнит-тесты (пароли, сроки по часовому поясу) |
| `npm run smoke` | Сквозной сценарий этапа 1 на запущенном сервере (**только тестовая БД**) |
| `npm run smoke:tasks` | Сквозной сценарий этапа 2 (задачи); запускать после `npm run smoke` |
| `npm run db:reset:local` | Пересоздаёт локальную D1 разработки |
