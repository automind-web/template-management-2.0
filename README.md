# AI Management — рабочий кабинет задач

Публикация: см. **[README_SITES.md](README_SITES.md)**.

## Структура

```
/app, /components      страницы и интерфейс (React, Tailwind 4, shadcn/ui на Radix) по макету AI-Management-Desktop
/components/settings   вкладки «Настроек системы»: компания, процесс, филиалы, участники, приглашения, подключения
/app/api/[...path]     единая точка API → server/router.ts
/server                серверные операции, проверка прав (permissions.ts), сессии, пароли
/server/ops            операции: setup, auth, invites, org, system, tasks (+ статистика — этап 4)
/server/workflow.ts    статусы и переходы компании, роли участника по задаче
/server/settings.ts    настройки компании (оформление, срок по умолчанию, приёмка, видимость, помощник)
/db/schema.ts          схема БД (Drizzle)
/drizzle               SQL-миграции
/config/company.ts     название, тема, статусы, переходы, правила, часовой пояс
/i18n/messages.ts      все тексты интерфейса (ru; заготовки kk, en)
/worker/index.ts       точка входа Worker (fetch, scheduled)
/.openai/hosting.json  привязки DB и BUCKET
```

## Безопасность (реализовано на этапе 1)

- Роль, филиал и членство читаются из БД **на каждом запросе** — перевод или отзыв действует со следующего запроса; при отзыве все сессии участника закрываются.
- Сессии хранятся как SHA-256 от токена; токены приглашений и кодов — тоже только хеши.
- Изменяющие запросы принимаются только со своего origin (CSRF).
- Ответы API — `Cache-Control: no-store, private`; секреты интеграций читаются только на сервере, наружу отдаётся лишь факт наличия (и только директору).

## Задачи (этап 2)

- Один серверный запрос `GET /api/tasks` для списка (и канбана на этапе 3): права → фильтры → счётчики по статусам и просрочке из того же набора условий.
- Каждое изменение несёт `version` и `opId`: повтор нажатия или доставки возвращает прежний результат без новой записи; при конфликте сервер отдаёт `409 version_conflict` с актуальной карточкой, клиент сохраняет введённый текст.
- История (`task_events`) хранит автора, время, прежнее и новое значение, а также снимок исполнителя, срока и статуса на момент события — основа статистики «на момент среза» (этап 4).
- Поиск без учёта регистра по кириллице: поле `tasks.search_text` (миграция `0001_task_search`).
- Файлы: содержимое в R2, метаданные в D1; скачивание `/api/attachments/:id` проверяет права по задаче.

## Интерфейс по макету (AI-Management-Desktop)

- Вход, активация компании, восстановление, новый пароль, приглашение — одна карточка по центру.
- Кабинет: боковое меню (Задачи, Ватсапп помощник, Статистика, Уведомления; внизу — Настройки системы и Профиль), шапка страницы с выбором филиала у директора. На телефоне — нижняя панель.
- Задачи: поиск (`/`), список-таблица и канбан, «Мои задачи / Все доступные», статусы со счётчиками, срок, исполнитель, «Найдено», выгрузка CSV. Канбан: переходы через меню «…» карточки.
- Карточка: поля правятся на месте (Ctrl+Enter / ⌘+Return — сохранить), справа исполнитель, срок, время, «Убрать срок», история.
- Разделы «Ватсапп помощник», «Статистика», «Уведомления» показывают заглушку до своих этапов (6, 4, 5) и будут сделаны по экранам 10–12, 21, 26 макета.
- Отличие от макета: токен Whapi не вводится в интерфейсе — по ТЗ все секреты задаются в настройках сайта Sites; вкладка «Подключения» показывает их состояние и способ восстановления.
